# PodereBot

Telegram bot for gates, heating, temperatures and sensors on a Raspberry Pi. ASP.NET Core, systemd.

## Requirements

.NET 10 SDK, `git`, `curl`, systemd (Linux). On the Raspberry Pi:

```sh
curl -sSL https://dot.net/v1/dotnet-install.sh -o /tmp/dotnet-install.sh
chmod +x /tmp/dotnet-install.sh
sudo /tmp/dotnet-install.sh --channel 10.0 --install-dir /usr/share/dotnet
sudo ln -sf /usr/share/dotnet/dotnet /usr/local/bin/dotnet
dotnet --info
```

## Install

```sh
git clone <repo-url> PodereBot
cd PodereBot
sudo ./install.sh   # creates a .env template and stops
nano .env           # fill TELEGRAM_API_KEY and ZEN_API_KEY
sudo ./install.sh   # builds, installs and starts the services
```

The bot starts at boot as `poderebot.service`. A watchdog checks `/api/status` every 10 minutes.

## Update

```sh
./patch.sh
```

Hard-resets to `origin/<branch>`, rebuilds and restarts. Works with or without `sudo`. Keeps `.env`, `db.json` and `users.json`.

Run `sudo ./install.sh` once after upgrading to a version that changed `install.sh`, since `patch.sh` and the systemd units are generated by it.

## Service

```sh
sudo systemctl restart poderebot.service
sudo systemctl status poderebot.service --no-pager
journalctl -u poderebot.service -f
```

## Files

| Path | Tracked | Purpose |
|---|---|---|
| `.env` | no | secrets, overrides `appsettings.json` through environment variables |
| `appsettings.json` | yes | pins, heating, AI endpoint/model, `Users` seed |
| `users.json` | no | runtime users, entitlements and topic subscriptions managed by `/adminpanel` |
| `db.json` | no | runtime state (heating program, gate access, subscriptions) |
| `usage.json` | no | daily token usage used by `/status` |

## Settings

`.env`:

```
TELEGRAM_API_KEY=...
ZEN_API_KEY=...
# SerialPort=/dev/ttyUSB0
```

Every `.env` key overrides the same key in `appsettings.json`.

`ZEN_API_KEY` is the OpenCode API key, valid for both Go and Zen.

### AI

```json
"AI": {
  "Endpoint": "https://opencode.ai/zen/go/v1/",
  "Model": "deepseek-v4.1-flash",
  "ReasoningEffort": "Low"
}
```

- `Endpoint`: `https://opencode.ai/zen/go/v1/` uses the Go subscription, `https://opencode.ai/zen/v1/` is Zen pay-as-you-go. The same key works for both.
- `Model`: any id from `https://opencode.ai/zen/go/v1/models`.
- `ReasoningEffort`: `None`, `Low`, `Medium`, `High` or `ExtraHigh`.
- `/status` reports the last 7 days of token usage and the estimated Go cost as a percentage of `WeeklyBudgetUsd`. Prices and time multipliers are fetched from `{Endpoint}models` every 6 hours; `InputPricePerMillion`, `CachedInputPricePerMillion` and `OutputPricePerMillion` are only fallbacks. Usage is kept in `usage.json`.
- Go requires the `x-opencode-session` header; the bot sends one per chat automatically.
- If the bot answers with the generic error, check `journalctl -u poderebot.service`: `api_key_expired` means the key in `ZEN_API_KEY` must be replaced with a new one from OpenCode Console.

Hardware defaults to embedded GPIO. Set `SerialPort` only if the pins are driven over a serial adapter.

### Heating and alerts

```json
"Heating": {
  "Antifreeze": { "Enabled": true, "ThresholdCelsius": 5.0 },
  "BoilerAlert": { "MaxContinuousHours": 4.0 },
  "TemperatureBand": { "MinCelsius": 5.0, "MaxCelsius": 30.0 }
}
```

Antifreeze wins over the program, over its suspension and over a manual switch-off. Notifications go to the subscribers of the `technical`, `heating` and `gates` topics; admins receive all of them.

### Gate access

```json
"Gates": { "RateLimit": { "MaxOpenings": 3, "WindowMinutes": 10 } }
```

The limit applies only to users without `admin` or `gate_controller`. When a shared access window expires, the users who used the gates receive a notice.

### API

`GET /api/status`, `/api/temperatures`, `/api/heating`, `/api/gates`, `/api/health`; `POST /api/temperature`. `/api/health` answers 503 when the Telegram connection or the database is unhealthy, and it is what the systemd watchdog checks.

Set `API_TOKEN=...` in `.env` to require the `X-Api-Token` header on every `/api/*` and `/mcp` request. With no token, the local-network restriction is the only guard.

Users are the `Users` seed in `appsettings.json` merged with the gitignored `users.json`, minus the ids under `Removed`. Each entry has `Id`, optional `Name`, `Entitlements` and `Topics`. The entitlements are `admin` (implies every other entitlement and every topic) and `gate_controller` (opens the gates at any time, without being an admin). The topics are `technical`, `heating` and `gates`. A user with no entry, or with no entitlement, is a normal user. `/adminpanel` (admin only) lists them as Telegram contacts and manages entitlements and topics; changes persist across `patch.sh`. A legacy `admins.json` is migrated once and then deleted. Admin commands are hidden from non-admins.
