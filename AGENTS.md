# AGENTS.md — PodereBot

## Project

.NET 10 ASP.NET Core bot running on a Raspberry Pi (Linux ARM). Controls gates, heating, and sends crypto trading alerts via Telegram. Single-project, no tests, no CI.

## Build & run

```powershell
dotnet build
dotnet run                    # uses mock GPIO drivers in Development
dotnet build /p:OutputPath=build   # production-style build (matches install.sh)
```

`TELEGRAM_API_KEY` must be set (loaded from `.env` file at startup via DotNetEnv).

The Telegram.Bot SDK comes from a custom Azure DevOps feed (see `PodereBot.csproj` `RestoreSources`).

## Hardware drivers

| Environment | Pin driver | Temperature driver |
|-------------|-----------|-------------------|
| Development (ASPNETCORE_ENVIRONMENT=Development) | `MockPinDriver` | `MockTemperatureDriver` |
| Production (`SerialPort` set) | `SerialPinDriver` (COM4 @ 115200 baud) | `OneWireEmbeddedTemperatureDriver` |
| Production (no `SerialPort`) | `EmbeddedPinDriver` (System.Device.Gpio) | `OneWireEmbeddedTemperatureDriver` |

GPIO pins configured in `appsettings.json` `Pins` section.

## Bot commands

Commands auto-register via `[CommandMetadata(Key, Description, Admin)]` attribute and reflection. Commands with `Admin = true` require the sender's user ID to be in `appsettings.json` `Admins` list.

Admin commands are also hidden from non-admins through Telegram command scopes: the public list is set as the default scope, and the full list is set per admin private chat (`BotCommandScopeChat`) at startup and lazily the first time an admin messages the bot. Hiding is cosmetic only; `Command.HandleAuthorization` still enforces access.

`/adminpanel` is the admin panel: it lists the current admins as clickable Telegram contacts, adds one by typed id or the `KeyboardButtonRequestUsers` picker, and removes one with confirmation. Additions go to `RuntimeAdmins`, removals to `RemovedAdmins`, both in the gitignored `admins.json` under the content root, and `AdminList.Get()` resolves `(Admins ∪ RuntimeAdmins) \ RemovedAdmins`. Runtime changes survive `patch.sh` and rebuilds; editing `Admins` in the repo still works. Removing an admin also clears their per-chat command scope and is refused when only one admin remains. `PendingInputRegistry` keeps the AI fallback from answering the typed id.

Interactive commands use `AttachEvents()`/`DetachEvents()` pattern for inline keyboard callbacks. Messages queued for deletion via `DeleteOnDetach()` are cleaned up on detach.

Bot language is **Italian**.

## REST API

All endpoints are restricted to local network (192.168.x.x, 127.0.0.1). Binds to `http://0.0.0.0:5050`.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/status` | Process uptime + memory (used by systemd watchdog) |
| POST | `/api/temperature` | Accept external sensor readings |

API endpoints auto-register via `IEndpoint` reflection (same pattern as commands).

## Heating

Heating program format: `hh:mm-hh:mm@temp/hh:mm-hh:mm@temp` (24h). `HeatingProgram.TryBuild()` validates intervals are non-overlapping and sorted. `HeatingProgramDaemon` polls every `PollIntervalSeconds` and applies temperature hysteresis with `ToleranceSeconds` delay.

## Database

Single-file JSON database (`db.json`) written to `AppContext.BaseDirectory` on every `Edit()` call. Reads and clones on every `Data` access. No migrations.

## Crypto trading (disabled)

The crypto alerts engine is **disabled**: `CryptoAlertDaemon` and its AI tools are commented out in `Program.cs` / `AiToolRegistry`, and the `/trading` command has been removed. The engine code (`Services/Background/CryptoAlertDaemon.cs`, `Lib/Trading/`) is kept for reference. It subscribes to the Binance WebSocket kline stream for `SOLUSDC` on a 1h timeframe, preloads ~50 historical klines, and runs `AtrStochRsiEmaStrategy`.

## AI usage

`UsageTracker` aggregates input, output and cached input tokens per day in `usage.json` (content root, gitignored), fed by every AI response. Each request's cost is computed when it is recorded, using prices and time multipliers fetched from `{AI:Endpoint}models` every 6 hours by `ModelPricing` (config prices act as fallback). `/status` sums the last 7 days and shows the cost as a percentage of `AI:WeeklyBudgetUsd`.

## Formatting

CSharpier (`.csharpierrc.json`): printWidth 140, tabWidth 4, no tabs.

## Deployment

`install.sh`: run from the repo with `sudo ./install.sh [user]` (defaults to `$SUDO_USER`). It derives all paths from the script location, requires a `.env` with `TELEGRAM_API_KEY` and `ZEN_API_KEY` (creates a template and stops if missing), chowns the repo to `user`, builds as `user`, and writes `poderebot.service` (`Restart=always`, `WorkingDirectory` set) plus the oneshot watchdog (`poderebot-wd.service` + timer).

`patch.sh` is generated by `install.sh` (gitignored). Run it as the repo user or with sudo: it derives its own directory, fetches and hard-resets to `origin/<current branch>`, stops the service, builds as the repo owner, then restarts it and prints the status. Untracked runtime files (`admins.json`, `db.json`, `.env`) survive the reset.

Systemd watchdog polls `GET /api/status` every 10 minutes; restarts the service if it fails.

## What is NOT here

- No tests (no test project, no test framework)
- No CI/CD (`.github/workflows/` is empty)
- No code generation, no migrations, no build artifacts to commit
- No monitoring, no structured logging export
